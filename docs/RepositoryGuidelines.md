# Repository Guidelines (Phase 3)

**Scope:** Persistence adapters only. **No business workflows** in repositories or Phase 3 services.

---

## 1. Placement

```
infrastructure/persistence/
  identity/     # Phase 2 IAM
  geography/
  agriculture/
  insurance/
  climate/
  engagement/
  platform/
```

Each package: JPA `@Entity` types + Spring Data `JpaRepository` interfaces (+ optional custom fragments).

Application ports (interfaces) may mirror repositories for Clean Architecture; Phase 3 may use Spring Data interfaces directly as ports to avoid empty indirection — document if ports are added later.

---

## 2. Rules

1. **No business rules** — no status transition logic, no premium calculation, no claim approval.  
2. **No HTTP / security concerns** — repositories do not read `SecurityContext`.  
3. **Soft delete** — default finder methods exclude `deleted = true`.  
4. **Transactions** — repositories participate in caller transactions; do not start long workflows here.  
5. **Naming** — `FarmerRepository`, `FarmBoundaryRepository`, …  
6. **Queries** — prefer method names; use `@Query` for spatial/JPQL/SQL. Native SQL allowed for PostGIS.  
7. **Pagination** — `Pageable` for admin lists; keyset methods for large observation tables.  
8. **Batch** — `saveAll`, JDBC batch where bulk ingest requires (climate) — keep APIs explicit.

---

## 3. Entity mapping standards

- UUID `@Id` assigned in factory/`@PrePersist` if not generated by DB  
- `@Version` on mutable aggregates  
- `AuditableEntity` base (or shared embeddable) for audit columns  
- Geometry via Hibernate Spatial (`Geometry` / `org.locationtech.jts`)

---

## 4. Caching strategy (documentation only — Phase 3)

| Data | Cache? | Notes |
|------|--------|-------|
| Crops, PolicyTypes, admin geography | Candidate (later) | Read-heavy, slow-changing |
| Farmers, Farms, Policies | No (Phase 3) | High consistency needs |
| Weather observations | No | High write/volume |
| RiskScore published | Optional short TTL later | |

Do not enable Spring `@Cacheable` in Phase 3 unless needed for tests — prefer documenting intent.

---

## 5. Connection pooling

HikariCP via Spring Boot:

- `maximum-pool-size` sized per environment (local 5–10; prod tune with DBA)
- `leak-detection-threshold` in non-prod
- Fail fast on startup if DB unreachable (`spring.datasource.hikari.initialization-fail-timeout`)

---

## 6. Testing expectations

| Test type | Tool |
|-----------|------|
| Migration from empty DB | Testcontainers PostGIS + Liquibase |
| Repository CRUD + constraints | `@DataJpaTest` or `@SpringBootTest` + Testcontainers |
| Spatial validity / intersects / area | PostGIS container |
| Unique partial indexes | Insert deleted + active duplicates |

---

## 7. Anti-patterns

- God repositories spanning multiple aggregates without need  
- Returning open `Stream` without clear lifecycle  
- Catching and swallowing constraint violations silently  
- Embedding GeoJSON strings instead of geometry types
